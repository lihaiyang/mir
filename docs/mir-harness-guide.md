# MIR Harness 上手

MIR Harness 是 MIR 自带的编码智能体：不用装 CLI、不用登录任何 Agent 账号，
只要给它一个 **OpenAI 兼容的接口地址 + API Key**，就能在编辑器里聊天、读代码、改文件、跑命令。

> 想了解实现原理（进程模型、ACP 协议、内核循环）看 [`docs/mir-harness.md`](./mir-harness.md)；
> 这篇只讲怎么用。

---

## 1. 你需要准备什么

- 一个 OpenAI 兼容的 `POST /chat/completions` 接口（官方 DeepSeek、自建网关、聚合网关都行），
  以及对应的 API Key；
- 接口最好支持 **流式输出**（SSE）和 **工具调用**（function calling）：
  - 只有流式 → 能聊天，但不会读写文件；
  - 两者都支持 → 完整能力（推荐）。

> 不需要单独安装 node，也不需要 `npx` 下载任何东西——MIR 用自己进程内的 Node 运行时启动内置 Agent。

---

## 2. 三步开始

### 第一步：填配置

打开 **设置**（标题栏齿轮，或 `Cmd+,`）→ 左侧 **ACP 智能体** → 找到
**MIR HARNESS（内置 AGENT）** 分区，填：

| 字段 | 说明 |
| --- | --- |
| 接口地址 | OpenAI 兼容接口根地址，通常以 `/v1` 结尾，例如 `https://api.deepseek.com/v1` |
| 接口密钥 | 你的 API Key（本地网关不需要就留着空，但至少模型列表里要能选到模型） |
| 默认模型 | 新建会话时使用的模型 |
| 模型列表 | 会话里可切换的模型，可给单个模型单独配 `apiBase` / `apiKey`（覆盖全局）；旁边的**从接口拉取模型**可以自动读取 |

其余（温度、单轮上限、上下文窗口、默认批准模式、系统提示词）按需调，保存即可。
配置会写入 `~/.mir-harness/config.json`，**新建会话时生效**。

填好接口地址和密钥后，点模型列表右上角的 **从接口拉取模型**（或让接口地址输入框失焦）就能自动拉一遍模型，
不用手抄模型 id。支持 OpenAI 兼容、Anthropic、Google Gemini、Ollama 以及返回 JSON 数组的通用接口；
接口地址没写 `/v1` 时会自动补。已经手工改过的模型列表只会被**追加**新模型，不会被覆盖。

### 第二步：新建会话

右侧「智能体」面板 → **MIR Harness** 卡片 → **新建会话**。
工作目录默认取当前项目根目录（也可以在设置里配「默认工作目录」）。

### 第三步：开始对话

在输入框里描述需求，`Enter` 发送、`Shift+Enter` 换行。
它会一边思考一边流式输出，需要动文件或跑命令时会弹出权限卡片。

## 3. 界面速览

| 区域 | 能做什么 |
| --- | --- |
| 会话头部 | 切换 **模式**（Ask / Code）、**模型**、**推理强度**；显示上下文用量 |
| 消息区 | 用户气泡、可折叠的「思考中」、工具卡片（读/写/搜索/命令）、计划卡、权限卡 |
| 输入框 | 处理中变成橙色「停止」按钮；发送按钮右侧可看当前状态 |
| 右栏面板 | 新建/断开/重启 Agent、查看运行日志、按 Agent 分组的会话历史、从注册表添加其它 Agent |

### 两个模式

| 模式 | 行为 |
| --- | --- |
| **Ask**（默认） | 写文件、执行命令前**一定询问**；只读操作（读文件、列目录、搜索）直接执行 |
| **Code** | 工作目录内的写文件/命令**自动批准**（命令用启发式判断是否只动工作目录；写文件任何时候都不能越出工作目录），适合放手让它改代码 |

需要它「先看再问」时用 Ask；连续改代码时切到 Code。

### 斜杠命令

| 命令 | 作用 |
| --- | --- |
| `/clear` | 清空当前会话的上下文（磁盘上的会话记录也会被重置，会话本身可以继续用） |
| `/status` | 查看当前模型、密钥状态、模式、消息条数、上下文占用、工作目录 |

---

## 4. 权限卡片

写文件、执行命令时会弹出卡片，三个按钮：

- **允许一次**：只批准这一次调用；
- **本会话总是允许**：本会话内同类操作不再询问（换个会话要重新授权）；
- **拒绝**：不执行，Agent 会收到拒绝结果并继续用它自己的方式回答。

卡片上会显示工具名、目标文件/命令、以及原始参数（可展开）。点右上角 × 等同拒绝。

---

## 5. 它能做什么

| 工具 | 说明 |
| --- | --- |
| `read_file` | 读文件（可指定起始行与行数，默认 400 行） |
| `write_file` | 创建或整文件覆盖写入（限制在工作目录内） |
| `list_dir` | 列目录（目录在前） |
| `search_files` | 用正则递归搜索文件内容 |
| `run_command` | 在工作目录执行 shell 命令（默认 60s，最长 600s） |

- 工具输出统一截断到 2 万字符（保留尾部），避免一次塞爆上下文；
- 写文件优先走编辑器文件系统，写完 MIR 会同步刷新已打开的文件。

## 6. 常见问题

**提示「需要先配置 MIR Harness 的 API Key」**
→ 设置里密钥为空。填好保存后**新建**一个会话即可（旧会话仍会报错，不用管它）。

**回复是「本轮失败：模型接口鉴权失败（HTTP 401/403）」**
→ 密钥不对、过期，或接口地址指向了错误的环境。可以用 `curl` 先验证一次：

```bash
curl -s http://127.0.0.1:3425/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"<model>","messages":[{"role":"user","content":"hi"}]}'
```

**模型下拉里没有我想要的模型**
→ 先点设置里的 **从接口拉取模型**；接口没返回的话再手动加一条（`id` 必填，`name` 是下拉里显示的名字）。
拉取失败时会显示原因：401/403 查密钥、`不是 JSON` 说明地址指到了网页、超时查网络或本地网关。

**会话历史在哪？**
→ 磁盘：`~/.mir-harness/sessions/`；界面：右栏面板的历史分组，点一行即可恢复（会回放历史消息）。

**上下文太长、回复变慢/报错**
→ 用 `/clear` 开一段新上下文；或者在设置里调小「上下文窗口」提醒自己。

**想用别的 Agent（Claude Code / Copilot / Codex…）**
→ 设置里「添加智能体」填命令，或「浏览注册表」挑一个；MIR 也内置了 Pi 和 DeepSeek Harness。

**怎么彻底重置？**
→ 退出 MIR，删除 `~/.mir-harness/`（配置 + 会话）即可；或者在面板里把 MIR Harness 条目删掉。

## 7. 和其它 Agent 的区别

| | MIR Harness | Pi / DeepSeek Harness 等 CLI Agent |
| --- | --- | --- |
| 安装 | 随 MIR 内置，零安装 | 依赖本机 CLI / `npx` 下载 |
| 模型来源 | 任意 OpenAI 兼容接口，换接口即换模型 | 由该 Agent 自己的配置决定 |
| 工具集 | 5 个基础工具（读/写/列/搜/命令） | 各 Agent 自带上限 |
| 多模态 | v1 不支持图片、音频、MCP | 视 Agent 能力 |

更多细节（配置文件字段、ACP 能力矩阵、内核循环、已知限制）见 [`docs/mir-harness.md`](./mir-harness.md)。
